# 作業手順書：オセロ・コマ回収戦（Googleスプレッドシート ＋ Gemini AI連携版）

## 1. コーディング・設計の技術目標（ポートフォリオ評価ポイント）
単なる「動くプログラム」ではなく、エンジニアとしての設計力・セキュリティ意識・外部API連携の実装力をアピールするため、以下の6つのルールを徹底して実装します。

1. **関心の分離（ロジック・UI・API通信の完全分離）**
   * ゲームのルール判定（データ配列の操作）、スプレッドシートへの描画処理、Gemini APIとの通信処理を別ファイル・別関数に完全に分けます。
2. **状態管理の一元化（Stateオブジェクト設計）**
   * 盤面データ・現在のフェーズ・ターン・ゲームモード・スコアなどを1つの `gameState` オブジェクトにまとめ、JSON形式で `PropertiesService` に保存・復元する設計にします。
3. **APIキーのセキュアな管理（セキュリティ意識）**
   * Gemini APIキーをソースコード内に直書き（ハードコーディング）せず、GASの `PropertiesService`（スクリプトプロパティ）に保存して安全に読み込む仕組みを作ります。
4. **プロンプトエンジニアリングと構造化出力（JSON指定）**
   * Gemini APIに盤面状況と合法手リストを渡し、プログラムで確実にパース（解析）できるよう「指定のJSON形式（選んだ座標と一言コメント）のみ」を返却させるプロンプトを設計します。
5. **GAS特有のパフォーマンス最適化（バッチ処理）**
   * スプレッドシートのセルを1マスずつ更新せず、必ず8×8の2次元配列を作り、`setValues()` や `setBackgrounds()` で一括反映させます。
6. **単一責任の原則とエラー耐性（フォールバック設計）**
   * 1関数1役割を徹底し、JSDocコメントを記載します。また、AIが不正な座標を返した場合やAPI通信エラー時でもゲームが止まらないよう、ランダム選択等に切り替える安全装置（フォールバック）を実装します。

## 2. 開発ステップ（全7フェーズ）

いきなりすべてを作ろうとせず、**「小さな単位で作る → 動作確認する → GitHubにコミットする」**のサイクルで進めます。

### Step 1：環境構築とファイル分割（設計の土台作り）
機能ごとにスクリプトファイルを分割し、見通しの良いプロジェクト構成を作ります。
* **作業内容**：
  1. 新規Googleスプレッドシートを作成し、拡張機能からGASエディタを開く。
  2. エディタ左側の「＋」からスクリプトファイルを機能別に分割して作成する。
     * `Main.gs`：エントリーポイント（`onOpen`、`onEdit`、全体の進行制御）
     * `GameLogic.gs`：オセロの反転判定、回収戦のルール判定、パス・勝敗判定
     * `GeminiClient.gs`：Gemini APIへのリクエスト送信、プロンプト生成、レスポンス解析
     * `View.gs`：スプレッドシートへの盤面描画、メッセージ・スコア表示
  3. カスタムメニュー（「2人対戦を開始」「Gemini AI対戦を開始」「APIキー設定」）を表示する `onOpen()` を実装する。
* **確認ポイント**：スプレッドシートを再読み込みし、上部メニューに独自メニューが表示されること。

### Step 2：データ構造の定義と初期化処理（`Main.gs` / `View.gs`）
要件定義書の「3.2 コマのデータ管理機能」をコードに落とし込みます。
* **作業内容**：
  1. 8×8の盤面配列を生成する関数 `createInitialBoard()` を作成する。各マスは `{ color, owner, state }` のオブジェクトを持つ。
  2. 中央4マスの初期配置を設定する（黒2・白2。**ゲーム開始時点の色に応じて `owner` も確定させる**）。
  3. 盤面配列を受け取り、スプレッドシートの `B2:I9` に色・チェックボックス・ステータス欄を一括描画する `renderBoard(state)` を作成する。
* **確認ポイント**：メニューから初期化を実行し、緑色の盤面と中央4コマ、右側のスコア・モード表示が綺麗に描画されること。
* **GitHub記録目安**：`feat: 初期盤面のデータ構造とUI描画処理を実装`

### Step 3：第1フェーズ（通常オセロ）の実装（`GameLogic.gs`）
まずは2人対戦モードで通常のオセロが遊べる状態を作ります。
* **作業内容**：
  1. 8方向を探索して反転可能なコマの座標リストを返す `getFlippableDiscs(board, r, c, player)` を実装する。
  2. `onEdit(e)` トリガーを作成し、チェックボックスがONになった座標を取得して配置処理を呼び出す。
  3. 配置時、`color` と `owner` に手番プレイヤーを設定し、挟んだコマは `color` だけを更新する（**`owner` は変更しない**）。
  4. パス判定（`hasValidMove`）と、双方置けなくなった際の第2フェーズ移行処理（`transitionToPhase2`）を実装する。
* **確認ポイント**：2人対戦モードでオセロが最後まで打て、パスや勝敗カウント、第2フェーズへの自動移行が正しく動くこと。
* **GitHub記録目安**：`feat: 第1フェーズ（通常オセロ・所有権記録）のロジックを実装`

### Step 4：第2フェーズ（コマ回収戦）と第3フェーズ（勝敗判定）の実装
このゲームの醍醐味である回収戦と勝敗判定を作ります。
* **作業内容**：
  1. `collectStep`（1：基本回収 / 2：追加回収）の状態を管理する処理を追加する。
  2. **ステップ1（基本回収）**：選択されたマスの `owner === player` であるか検証し、合致すれば `state = 'COLLECTED'` にしてスコア加算。対象コマがない場合は自動パス。
  3. **ステップ2（追加回収）**：選択されたマスの `color === player || owner === player` であるか検証し、合致すれば回収して手番交代。対象がない場合はスキップして交代。
  4. 盤上の残りコマ数が `0` になったら第3フェーズへ移行し、スコア比較による勝敗メッセージを表示する。
* **確認ポイント**：所有権のあるコマが相手に裏返されていてもステップ1で回収できること、ステップ2で追加回収ができること、全回収で決着がつくこと。
* **GitHub記録目安**：`feat: 第2フェーズ（コマ回収戦）および勝敗判定を実装`

### Step 5：Gemini API連携機能の実装（`GeminiClient.gs`）
一人プレイモードの核となるGemini API通信とAI思考を作ります。
* **作業内容**：
  1. メニューからダイアログ（`Browser.inputBox` 等）を開き、ユーザーが自分のGemini APIキーをスクリプトプロパティに保存できる設定関数 `setGeminiApiKey()` を作る。
  2. `UrlFetchApp.fetch()` を用いて Gemini API（`gemini-2.5-flash` 等）にリクエストを送る共通関数を作成する。
  3. **第1フェーズ用AIプロンプト**：現在の8×8盤面と「AIが置ける合法手リスト」をGeminiに渡し、`{"row": 2, "col": 3, "comment": "角を狙います！"}` のようなJSON形式で次の1手を返却させる。
  4. **第2フェーズ用AIプロンプト**：盤面状況と「AIが回収可能なマスリスト（ステップ1用・ステップ2用）」を渡し、どのコマを回収すべきか判断させる（AI側も記憶・推測しながら選ぶ演出を入れるとより面白くなります）。
  5. **フォールバック処理**：万が一APIがエラーを返したり、選択肢にない座標を返した場合は、合法手リストの中から自動で1つ選ぶ安全処理を組み込む。
* **確認ポイント**：Gemini AI対戦モードを開始し、プレイヤーが打った後に「Gemini思考中…」と表示され、AIがコマを配置・回収し、メッセージ欄にAIのコメントが表示されること。
* **GitHub記録目安**：`feat: Gemini APIを用いた一人プレイ（AI対戦）機能を実装`

### Step 6：エッジケースの検証とリファクタリング
意図しない操作や通信トラブルで壊れないかテストし、コードを磨き上げます。
* **テスト項目**：
  * APIキー未設定の状態で「Gemini AI対戦」を選んだ際、親切なエラー案内が表示されるか。
  * 不正なマスをクリックしたとき、データや手番が壊れず警告メッセージだけが出るか。
  * 連続パスが発生したときに無限ループにならず正しくフェーズ移行・ターン交代するか。
* **リファクタリング**：重複している処理を共通関数にまとめ、変数名やJSDocコメントを整える。

### Step 7：GitHubポートフォリオとしての仕上げ（`README.md` 整備）
採用担当者や他の開発者が見て「技術力が高い！」と思う状態に仕上げます。
* **作業内容**：
  1. すべての `.gs` ファイルをGitHubリポジトリにコミットする。
  2. スプレッドシートでGemini AIと対戦している画面のスクリーンショットを撮り、`README.md` に貼る。
  3. `README.md` に「ゲームの概要・独自ルール」「工夫した技術ポイント（Gemini APIとのJSON構造化連携・バッチ処理・状態管理など）」「導入手順（コードのコピペ方法とAPIキーの設定手順）」を記載する。
