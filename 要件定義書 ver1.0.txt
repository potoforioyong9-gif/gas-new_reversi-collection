# 要件定義書：オセロ・コマ回収戦（Googleスプレッドシート ＋ Gemini AI連携版）

## 1. プロジェクト概要
* **プロジェクト名**：オセロ・コマ回収戦（Othello Piece Recovery Game with Gemini AI）
* **開発目的**：通常のオセロの戦略性に加え、「誰がどのマスにコマを置いたか（所有権）」という記憶要素と終局後の回収戦を組み合わせたオリジナルボードゲームの実装。さらに、**一人プレイ時にGemini APIを対戦相手（CPU）として組み込み**、AIと対局・回収戦を楽しめるシステム構築。Google Apps Script（GAS）と外部API連携を活用した高度なポートフォリオとしてGitHubで公開する。
* **ターゲットユーザー**：ボードゲームとAIの組み合わせに興味があるユーザー（GoogleアカウントおよびGemini APIキーを持つ利用者）。

## 2. システム構成・動作環境
* **プラットフォーム**：Google スプレッドシート
* **使用言語**：Google Apps Script（JavaScript）
* **外部連携**：**Gemini API**（一人プレイ時のCPU思考として使用）
* **データ保持方式**：スプレッドシートのセル表示（UI）、`PropertiesService`（内部データ管理）、およびスクリプトプロパティ（APIキー管理）。

## 3. 機能要件（主要機能）

### 3.1 ゲーム進行・フェーズ管理機能
ゲームは以下の3つのフェーズで進行し、システムが自動で状態遷移を制御する。対局開始時に「2人対戦モード」または「Gemini AI対戦モード」を選択できる。

| フェーズ | 名称 | 概要・遷移条件 |
| :--- | :--- | :--- |
| **第1フェーズ** | **通常のオセロ** | 8×8の盤面で標準的なオセロのルールに基づき対局を行う。双方（またはプレイヤーとGemini AI）とも合法手がなくなった時点で第2フェーズへ移行する。 |
| **第2フェーズ** | **コマ回収戦** | 第1フェーズの勝者（盤上の色数が多いプレイヤー）を先攻とし、交互に盤上のコマを回収する。盤上のコマがすべて回収された時点で第3フェーズへ移行する。 |
| **第3フェーズ** | **勝敗判定** | 最終的な回収コマ数を集計し、勝敗（勝利・敗北・引き分け）を判定して画面に表示する。 |

### 3.2 コマのデータ管理機能（コアロジック）
盤上の各マス（全64マス）について、システム内部で以下の3つの属性を常に保持・更新する。
* **現在の色**：`黒` / `白` / `なし`（第1フェーズで挟まれると反転する）
* **所有権**：`黒` / `白`
  * **初期配置の4コマ**：ゲーム開始時点の色（最初から配置されている黒コマは黒の所有、白コマは白の所有）によって最初から決定する。
  * **プレイヤー（またはGemini AI）が置いたコマ**：配置したプレイヤーに所有権が決定する。
  * ※一度決定した所有権は、第1フェーズで色が反転しても**絶対に変化しない**。
* **状態**：`空き` / `盤上` / `回収済み`

### 3.3 第1フェーズ（通常オセロ）のルール仕様
* 中央4マスの初期配置（黒2・白2：それぞれの所有権は初期の色に依存）から開始する。
* プレイヤー対戦 / Gemini AI対戦の切り替え：
  * **2人対戦**：交互に人間が操作する。
  * **Gemini AI対戦**：プレイヤーは黒、Gemini AIは白を担当。プレイヤーがチェックボックスで打った後、GAS経由で現在の盤面データをGemini APIに送信し、AIが打つべき最適な座標を返却させて自動でコマを配置する。
* 合法手・パス判定：相手のコマを挟めるマスにのみ配置可能。合法手がない場合は自動パス。
* 終了判定：両者ともに合法手がなくなった時点で終了し、盤上のコマ数（現在の色）を比較して多い方を第2フェーズの先攻とする（同数の場合は黒先攻）。

### 3.4 第2フェーズ（コマ回収戦）のルール仕様
1ターンにつき以下の手順でコマを回収する（Gemini AI対戦時も同様に、AI側の回収手番はGemini APIに判断させる）。
1. **ステップ①（基本回収）**：
   * 現在の手番プレイヤー（またはGemini AI）が **「自分が置いた（または初期配置で自分の色だった）所有権のあるコマ」** を盤上から1個選択して回収する（現在の色は問わない）。
   * 回収できた場合、手持ちスコアを+1し、ステップ②へ進む。
   * 回収できるコマが盤上に1つもない場合、そのターンは即座に終了（パス）し、次のプレイヤー（またはAI）へ交代する。
2. **ステップ②（追加回収）**：
   * ステップ①で回収に成功した場合のみ実行可能。
   * 盤上からさらに1個回収できる（1ターンにつき最大1個、ステップ①と同じコマは選択不可）。
   * 対象条件：**「現在の色が自分の色であるコマ」** または **「自分が所有権を持っているコマ（現在の色は問わない）」**。
   * 対象となるコマが存在しない場合はステップ②をスキップし、次の手番へ交代する。

### 3.5 画面表示・UI/UX要件
* **ゲーム初期化・モード選択機能**：スプレッドシート上部のカスタムメニューから「2人対戦を開始」「Gemini AI対戦を開始」などを選択して初期化できること（※AI対戦時は初回にAPI設定が必要な旨の案内を実装）。
* **盤面描画（8×8グリッド）**：
  * セルの背景色・文字表示で「空きマス」「黒コマ」「白コマ」「回収済みマス」を視覚的に区別できること。
  * **重要仕様**：盤面（UI）には「所有権が誰にあるか」を表示せず、プレイヤー自身の記憶に委ねる設計とする。
* **操作インターフェース**：各マスのチェックボックス操作をトリガー（`onEdit`）として検知し、直感的にコマの配置・回収ができること。
* **ステータス表示エリア**：
  * 現在のゲームモード（2人対戦 / Gemini AI対戦）
  * 現在のフェーズ（第1フェーズ / 第2フェーズ・ステップ1 / ステップ2 / 終了）
  * 現在の手番プレイヤー（黒 / 白 ※AI思考時は「Gemini思考中…」等を表示）
  * 双方の回収済みコマ数（スコア）
  * システムメッセージ（エラー案内、パス通知、勝敗結果、AIからのコメント等）

## 4. 非機能要件
* **外部API連携の安全性**：Gemini APIキーはスクリプトプロパティ（PropertiesService）に安全に保存し、コード内に直書きしない設計とする。
* **保守性・可読性**：GitHubで公開するため、変数名や関数名を明確にし、API通信処理は専用ファイル（`GeminiClient.gs`等）に分離する。
* **エラー耐性**：API通信のタイムアウトやエラーが発生した場合に備え、ゲームがクラッシュしないフォールバック処理や案内メッセージを入れる。
